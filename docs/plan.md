# 多阶段交付计划

## 执行原则

这是时间紧迫的冰岩后端实习任务，不是长期维护产品。首先完成可验收、用户能理解的 P0 查询闭环，再根据剩余时间决定是否扩展。
不把全部八章设为无条件完成目标，也不为赶进度删除已选功能的必要语义与安全校验；做不完时缩小范围并如实说明。
保留统一 dynamic client、SQL 前后端解耦、客户端 WHERE 求值和真实集群 E2E。不要提前构建通用框架或增加任务书外功能。
阶段是范围分组，不是单次开发批次；每阶段进一步拆成独立小功能，每次只完成一个经用户同意的功能。
本轮只修改文档，以下阶段均未开始；依赖兼容性、真实集群、实现、测试结果均为未验证。
此前仅观测到 Go 版本输出及远端配置，不等于工具链、集群或验收可用。

### 强制审查闸门

每个独立功能的流程：明确本次范围 → 实现与必要测试 → 输出审查说明 → **暂停**。
必须收到用户代码审查后的明确确认，才可开始下一个功能；同一阶段内也不能自动继续。
有修改意见时仅修复当前功能，重新测试和汇报，再次等待确认。没有回复、测试通过或此前笼统授权都不等于通过审查。

每次功能完成必须输出：

1. **变更摘要**：功能范围、修改文件及未实现内容。
2. **核心数据结构**：字段含义、为什么需要，附对应源码位置。
3. **关键调用链**：从输入到结果的实际函数路径。
4. **设计取舍**：最简单可行方案、必要抽象与没有做的扩展。
5. **测试结果**：实际命令、通过/失败/未运行；注明离线还是实集群，未验证事项和阻塞原因。
6. **审查与提交状态**：当前差异、拟议提交消息，明确等待确认；未提交不得写成已提交。

功能及其必要测试作为一个提交单位，通常不超过 200 行；不可分割的小改动不为凑行数强拆。
未来仅在用户明确授权提交时执行 commit，原则上在该功能审查确认后提交；提交授权不等于授权自动开发下一个功能。
本轮不得编码、安装依赖、改环境、commit 或 push。

| 优先级 | 阶段 | 交付内容 | 完成门槛（均尚未验证） |
| --- | --- | --- | --- |
| P0 | M0 工程基线 | Go 工具链、最小结构、真实测试集群 | 最小构建/测试可运行，明确测试 context 且 API 可访问 |
| P0 | M1 SQL 前端 | lexer、位置、SELECT AST、递归下降、EOF | 测试 1-1、1-2，无需集群 |
| P0 | M2 基础查询 | CLI 参数、三表、dynamic List、投影、JSON | 实集群测试 2-1、2-2 |
| P0 | M3 WHERE | 类型、优先级、括号、三值逻辑 | 测试 3-1、3-2，必要语义单测与实集群闭环 |
| P1 | M4 条件写入 | UPDATE/DELETE、patch、安全校验、失败汇总 | 测试 4-1、4-2，字段保留与部分失败验证 |
| P1 | M5 创建资源 | INSERT、manifest、创建校验 | 测试 5-1、5-2，重复创建不覆盖 |
| P2 | M6 通用资源 | Discovery、Pointer、AS、CAST、通用 CRUD | 测试 6-1，版本/scope/verbs/写保护验证 |
| P3 | M7 实际指标 | 两张只读表、Quantity 汇总 | 测试 7-1，固定样本与实集群指标分别验证 |
| P3 | M8 CRD 与特殊能力 | CRD/CR、版本、发现失败、Review | 测试 8-1、8-2，通用路由及能力边界验证 |
| 贯穿 + 冻结 | M9 验收交付 | 每功能测试、文档、质量检查、最终回归 | 已承诺范围可复现，未完成/未验证内容明确，无临时文件或凭据进入交付 |

优先完成 P0，再申请进入 P1；P2/P3 只有在已有闭环稳定、冻结时间充足且用户明确确认后才启动。
允许在 P0、P1 或 P2 完成后冻结交付；低优先级未开始项明确列为未实现，不称为全八章验收通过。
M9 不等所有功能写完才开始；测试、复现记录和交付准备随每个功能推进。
在用户提供截止时间后共同确定绝对冻结时间，默认预留最后约 20% 可用时间用于回归与交付（含审查时间），不能用 P2/P3 消耗它。
截止时间尚未提供，冻结日期未确定，不能据此承诺完成时间。

## M0（P0）：最小工程与环境

- 只验证 Go 工具链能构建和运行最小测试，创建当前所需 module/入口，不预建未来包与接口。
- 只保证独立真实 Kubernetes 测试环境及明确 context 可用；优先复用合适的现有测试环境，否则在获准后准备 minikube。
- 核实 API 访问、namespace 与基础资源可用；若环境阻塞，明确报告未验证，不用 fake 结果代替。
- 两个独立交付单元：最小工程可构建、真实测试环境可访问；每个单元完成后暂停审查。
- 不在 M0 要求 CI、Makefile、全面质量工具安装、fuzz、完整夹具或 Metrics Server。
- client-go 等依赖在首次使用时确认兼容性并固定版本，不提前安装后续阶段依赖。
- 二进制、临时 kubeconfig、日志和实验文件写 `tmp/`；正式可复用夹具按功能加入。
- 保留现有远端 `https://github.com/Palm0palM/kubesql`，无需另建仓库；不在此阶段自动 push。

## M1（P0）：可独立验证的 SQL 前端

- 逐字符扫描关键字、标识符、星号、逗号和分号，预留字符串、数字与引号 token 扩展。
- 实现任务书 SELECT 最小文法，生成符合样例的 JSON AST，星号保持独立节点。
- 解析器通过单元测试验证 JSON AST，不默认增加任务书外的 `--parse-only` CLI 功能。
- 必要测试覆盖大小写、换行、空输入、尾随垃圾、缺列和缺 FROM；引号测试随实际语法加入。
- 强制错误样例 `SELECT name, FROM deployments;` 定位到第 1 行第 14 列。
- 独立功能建议顺序：逐字符 token 与位置 → 最小 SELECT AST/parser → 语法错误与 EOF 校验；每项附必要测试后暂停。
- 全面 fuzz 与额外 Unicode/异常输入覆盖后置，不阻塞 SELECT 验收。

## M2（P0）：三表查询闭环

- 实现 stdin/flags/JSON 输出与 clientcmd 参数优先级，支持请求取消和超时。
- 静态绑定 namespaces、deployments、ingresses；未知表/列拒绝且不发送 API 请求。
- List 分页，保留数字和 NULL；Ingress 只读 defaultBackend.service，不误读 rules 后端。
- 单元/HTTP 测试 namespace 默认、context 覆盖、--all-namespaces 和集群 scope。
- 正式保存第 2 章夹具与 SQL；真实集群测试 2-1 使用包含断言，2-2 按行集合比较。
- 独立功能建议顺序：stdin/flags/JSON → kubeconfig 与 scope → Namespace 查询 → Deployment 查询 → Ingress 与星号投影；每项完成后暂停。

## M3（P0）：过滤语义

- 扩展 lexer 和 parser，分层实现 OR/AND/NOT/比较/IS NULL 与括号。
- 类型化求值，整数/小数精确比较；未知列即便候选为空也报错。
- 测试完整三值逻辑、NOT UNKNOWN、数字 10 > 2、跨类型错误、列对列比较、字符串转义。
- 新增第 3 章夹具，真实执行四条输入并验证集合，特别区分 `= NULL` 与 `IS NULL`。
- 独立功能建议顺序：字面量与比较 → AND/OR/NOT/括号 → NULL/IS NULL 三值逻辑 → 查询过滤接入；每项完成后暂停。
- P0 结束后先回归第 1–3 章并提供可复现查询说明，再由用户决定进入 P1 或冻结。

## M4（P1）：安全 UPDATE/DELETE

- 扩展 AST/文法，多赋值，复用 WHERE；缺少 WHERE 为 E_WHERE_REQUIRED。
- 列与值校验先于写入；确定全部匹配集合后再发写请求。
- JSON Patch test resourceVersion；目标 add/replace/remove；映射必须整体替换。
- 验证 replicas、Ingress 原后端存在性和 Service 名称，保留端口及未指定字段。
- 删除使用普通 API 请求，不移除 finalizer、不等待完全消失。
- fake reactor/httptest 模拟一个对象失败而后续成功，检查标识、原因、计数和非零退出码。
- 真实验证 4-1 修改前后镜像、selector、template、端口一致；4-2 从独立准备状态开始，指定对象删除等待最长 120 秒。
- 独立功能建议顺序：条件写语法与 WHERE 闸门 → replicas 精确更新 → labels/annotations 替换 → Ingress 名称更新 → DELETE → 多对象失败汇总；每项完成后暂停。
- 共享写入基础设施中的安全校验先到位再接 API，不能把未受保护的写操作当可交付功能。

## M5（P1）：INSERT 与 manifest

- 单 VALUES 元组、仅 manifest 列；SQL `''` 解码后再独立解析 JSON。
- 拒绝非法 JSON、非对象、GVK 不符、跨 namespace、服务器管理字段、缺 name/generateName。
- manifest 成为可读列且扩展 SELECT *，UPDATE manifest 仍禁止。
- 正式夹具分为 preparation 与 targets；targets 仅作断言，不提前 apply。
- 第 5-1 章由 SQL 创建 Namespace，等待 Active 后创建 Deployment。
- 第 5-2 章重复创建验证 AlreadyExists、汇总格式、退出码及原对象未被覆盖。
- 独立功能建议顺序：INSERT 与分层 JSON 解析 → manifest 查询 → Namespace 创建 → Deployment 创建 → Ingress 创建/重复失败；每项完成后暂停。
- P1 结束回归第 1–5 章，再评估 P2；剩余时间不足时冻结当前已验证闭环。

## M6（P2，可选扩展）：通用内置资源

- Discovery 快照保留版本优先顺序、scope、verbs 和部分组错误；严格组间歧义判断。
- 支持双引号精确表名、双引号 Pointer 列、AS 和受限 CAST JSON。
- 通用列与原三表便捷列共存，复用已完成的查询/写入引擎。
- 测试 Pointer 转义、数组读取、缺失路径、已有父对象下添加叶子、对象/数组输出与整对象替换。
- 测试 SQL NULL 移除和 JSON null 保存、超过 2^53 的整数读取/比较/写入。
- 对根路径、metadata 祖先、受保护字段及转义绕过做负向测试；错误不得泄露 Secret。
- 固定 Discovery 测试覆盖：同组多版本、跨组同名、preferred 缺资源、显式版本不回退、缺 verb、子资源拒绝。
- 真实执行 6-1 五种资源查询与 ConfigMap 更新；额外查询常见集群级资源验证 scope。
- 独立功能建议顺序：引号标识符与 AS → Pointer 读取 → Discovery 路由与版本/scope/verbs → Pointer 安全写入 → CAST 与 NULL 赋值；每项完成后暂停。
- 不为后续所有 API 搭建插件或策略框架，仅扩展现有资源描述与直接执行路径。

## M7（P3，可选扩展）：Metrics

- 实现 pod_metrics/node_metrics，只读，沿用列检查、过滤和输出。
- 固定样本验证 150m/83886080 bytes 与 250m/536870912 bytes。
- 加入亚毫核容器样本，证明先累加 Quantity 再舍入，而非分别舍入后累加。
- 测试未安装/不可用、Forbidden、空结果和写操作拒绝。
- 真集群创建双容器 Pod，Ready 与指标采集等待最长 180 秒；只断言一行、身份及非负整数，不要求真实用量等于任务书示例。
- 进入本阶段才准备 Metrics Server；独立功能为 Pod 指标、Node 指标、不可用/权限语义，每项完成后暂停。

## M8（P3，可选扩展）：CRD、聚合 API 与能力边界

- 保存第 8 章 CRD/实例夹具；明确分步创建、等待 Established、等待 Discovery 可见，再创建实例。
- 执行陌生 gadgets 的 SELECT/UPDATE/INSERT/DELETE，确认未指定 message 字段保留。
- 执行 ClusterNote 与 CRD 本身查询，传入无关 namespace 也不影响集群级资源。
- 增补 CRD 本身通过 SQL 创建及其通用字段修改/删除测试，不能只证明读取 CRD。
- 测试多 served version、显式版本、schema 拒绝、RBAC、不可变字段和版本冲突的错误传播。
- HTTP 模拟聚合 API 部分失败和 create-only Review，验证健康组可用、不把失败组当不存在、不要求 Review name。
- 不增加 Widget/ClusterNote 专用 Go 类型，不依赖 plural 猜测或 spec.replicas 假设。
- 独立功能建议顺序：陌生 namespaced CR 闭环 → 集群级 CR/CRD → 多版本与服务端错误 → 部分发现失败/create-only 能力；每项完成后暂停。
- M7/M8 均不是时间紧迫时的默认承诺；启动某个小功能不代表授权一次完成整个阶段。

## 测试组织与安全

按当前功能需要选择纯单元、fake/HTTP 协议和显式实集群 E2E，不追求每个功能都有三套测试基础设施。
每个功能必须有必要测试；CI、全面 fuzz、race 和任务书外的额外边界覆盖可以后置，不能后置 NULL 语义、scope、写保护等已选功能的必要验证。
fake client 不等价于 API Server，不可用它证明 JSON Patch test、默认值和 schema 的真实行为。
实集群测试通过 build tag 或显式环境配置启用，必须指定专用 context；拒绝隐式使用当前生产 context。
测试前置配置缺失应明确失败；默认离线套件不运行 E2E。选入交付范围的功能缺实集群验证时标为未验证；未选 M7 时不因缺 Metrics 阻塞 P0/P1 交付，也不声称指标通过。
夹具创建与清理仅针对本套件登记的名称和独立测试集群；不得全局删除 Namespace 或清理用户 CRD。
每个破坏性用例独立准备，不依赖上一个用例的副作用；失败保留脱敏诊断到 `tmp/`。
JSON 比较保留数字类型，按行集合而非顺序断言；INSERT 只比较目标明确字段，不比较服务端默认时间戳等。

## M9：贯穿开发的质量与功能冻结

**随每个功能执行**：gofmt、相关单测、已有测试回归、必要实集群用例、审查说明、使用/复现记录及临时文件检查。记录实际执行命令，不把计划命令当成结果。

**每个优先级闭环后执行**：回归已完成章节、整理已实现/未实现/未验证清单，检查剩余时间，等待用户决定扩展或冻结。

**冻结阶段**（预留最后约 20% 时间，实际日期待用户确认）：

1. 停止新增功能、抽象和非必要重构。仅修复交付范围内阻塞验收的问题，每项修复仍暂停审查。
2. 在独立真实集群回归已确认交付范围对应的任务书用例；未做章节明确列为未实现，未实际执行用例明确列为未验证。
3. 按任务书运行 `go test ./...`、`go vet ./...`、`staticcheck ./...`，记录结果；不因时间紧迫虚构通过。
4. 运行 `go fix`、兼容版本 modernize 和 deadcode 检查；审查建议后才改动，不盲目删除或自动套用。改动重新回归与审查。
5. 工具不可用或检查未执行则注明未验证及原因；CI、全面 fuzz/race 不作为当前功能闭环的前置门槛，有余力再补。
6. 文档只描述实际交付能力，包含安装、stdin、参数、输出、必要的写入风险和实集群复现入口；未实现 Metrics/CRD 不写成可用功能。
7. 检查 tracked 文件及凭据泄漏；二进制、日志、覆盖率和实验产物仅在 `tmp/`。最终汇报范围、证据和限制，等待验收。
8. commit/push/发布必须有明确授权，本轮不执行。冻结本身也不能绕过逐功能审查。

## 提交节奏与交付物

按完整小功能及其测试少量多次提交，通常单 commit 不超过 200 行，不机械拆散不可分割修改。
消息使用无 emoji 的 Angular 风格，例如 `feat(parser): parse select statements`、`test(engine): cover null filtering`。
提交前只暂存本次相关文件，保留已有用户改动；大生成文件/依赖变更按职责单独解释。
项目暂无实现，本轮不创建功能提交，也不把本地环境尚未核实的事项写成通过结果。

最终交付包括已确认范围的源码、go.mod/go.sum、必要单元/协议/E2E 测试、正式夹具、复现命令和文档；Makefile/CI 仅在确实实现时纳入，不作为无条件交付项。
架构与计划属于正式设计交付；试验笔记、下载工具、临时 YAML/SQL、运行输出不属于交付，全部归入 `tmp/`。
工具若需要临时目录/报告路径，应显式指向 `tmp/`；不修改用户全局 Go 缓存或已有 kubeconfig。
